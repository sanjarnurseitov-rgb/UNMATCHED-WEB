# Unmatched Match Tracker

Веб-приложение для учёта матчей по настольной игре **Unmatched** с дашбордом
статистики. База данных — ваша существующая Google Таблица; приложение
читает и пишет в неё напрямую через Google Sheets API.

Идентификатор таблицы уже прописан по умолчанию:
`15IJy050me3WkkI2vYf10tMhCFCKF0dglRY_HaBF96vQ`

---

## 1. Рекомендация по стеку

| Слой | Выбор | Почему |
|---|---|---|
| Framework | **Next.js 15 (App Router) + TypeScript** | Один проект даёт и UI, и серверные API-роуты. Не нужен отдельный бэкенд, не нужен второй хостинг. Server Components умеют отдавать статистику сразу в HTML — дашборд открывается мгновенно. |
| UI | **React 19 + Tailwind CSS v4** | Тёмная «игровая» тема собирается из CSS-переменных, без UI-кита. Быстро и без зависимостей. |
| Графики | **Recharts 3** | Декларативные SVG-графики, отлично дружат с React 19 и SSR. |
| Sheets | **googleapis** (официальный клиент) | Сервисный аккаунт, `values.append`, `batchUpdate`. Читается только на сервере. |
| Валидация | **Zod** | Одни и те же схемы для клиента и API-роутов. |
| Хостинг | **Vercel** | Бесплатный тариф, `NEXT_PUBLIC`/env-переменные, автодеплой из Git. |

**Почему не low-code (Apps Script / Airtable / Notion):** таблица уже
сложилась под конкретную форму ответов, а расчёт винрейтов и синергий —
это агрегация по 894 строкам с ветвлением по режиму. Apps Script справился бы
с записью, но дашборд с интерактивными графиками и drill-down’ом в нём
пришлось бы собирать вручную, и каждая правка статистики превращалась бы в
правку формул. Next.js даёт и форму, и аналитику, и запись в ту же таблицу.

**Альтернативы**, если нужен результат ещё быстрее:

- **Google Apps Script + Google Forms** — если приложение вообще не нужно,
  а достаточно формы с сводкой. Пишет в ту же таблицу, формулы считают
  винрейты. Ноль хостинга, но нет дашборда и графиков.
- **Retool / Appsmith** поверх таблицы — дашборд за час, но кастомная логика
  (синергии, нормализация имён) пишется неудобно, и запросы к Sheets идут
  через их runtime, что бьёт по лимитам.

### Ключевой код интеграции

Всё общение с таблицей изолировано в `src/lib/sheets.ts`.

```ts
// src/lib/sheets.ts
function getSheetsClient(): sheets_v4.Sheets {
  if (sheetsClient) return sheetsClient;

  const inline = process.env.GOOGLE_SERVICE_ACCOUNT_JSON;
  const credentials = inline
    ? JSON.parse(inline)
    : {
        client_email: process.env.GOOGLE_SERVICE_ACCOUNT_EMAIL,
        // В .env переносы строк хранятся как \n — превращаем их обратно.
        private_key: (process.env.GOOGLE_PRIVATE_KEY || '').replace(/\\n/g, '\n'),
      };

  const auth = new google.auth.GoogleAuth({
    credentials,
    scopes: ['https://www.googleapis.com/auth/spreadsheets'],
  });

  sheetsClient = google.sheets({ version: 'v4', auth });
  return sheetsClient;
}
```

**Чтение** — вкладки адресуются по названию, ID вкладок не хардкодятся:

```ts
async function readRange(range: string): Promise<string[][]> {
  const client = getSheetsClient();
  const res = await client.spreadsheets.values.get({
    spreadsheetId: spreadsheetId(),
    range,                       // например: "'Ответы на форму (3)'!A1:V"
  });
  return (res.data.values ?? []).map((row) => row.map((c) => (c == null ? '' : String(c))));
}
```

**Запись матча** — новая строка дописывается в конец, ровно в том формате,
который создаёт Google Форма, поэтому существующие формулы и сводные вкладки
продолжают работать:

```ts
await client.spreadsheets.values.append({
  spreadsheetId: spreadsheetId(),
  range: `'${MATCHES_TAB_TITLE}'!A:V`,
  valueInputOption: 'USER_ENTERED',     // дату Google сам разберёт как дату
  insertDataOption: 'INSERT_ROWS',
  requestBody: { values: [row] },
});
```

**Режимы работы.** Провайдер выбирается автоматически (`src/lib/sheets.ts`):

| `DATA_SOURCE` | Что делает | Когда нужен |
|---|---|---|
| `auto` (по умолчанию) | `api`, если есть ключи; иначе `public` | обычный режим |
| `api` | полный доступ: чтение + запись | продакшен |
| `public` | публичный CSV-экспорт, только чтение | демо без ключей |
| `snapshot` | встроенный JSON-снимок, только чтение | оффлайн-разработка |

Если `api` падает (отозванный ключ, опечатка в JSON), загрузчик данных
автоматически откатывается на публичный режим — дашборд не «упадёт» в
500, а просто покажет данные.

## 5. Статистика: что и как считается

Всё считается из сырых строк матчей — сводные вкладки таблицы
(`2vs2`, `1vs1`, `HeroProfile`…) не используются как источник истины,
потому что они разошлись с фактическими матчами.

Движок — `src/lib/stats.ts`.

```ts
// Победа игрока определяется по номеру места, а не по имени:
// 1 vs 1 -> 'Игрок 1' / 'Игрок 2', 2 vs 2 -> 'Команда 1' / 'Команда 2'
function winningSeats(match: Match): Set<number> {
  const seats = new Set<number>();
  if (match.mode === '1v1') {
    if (match.winner === 'p1') seats.add(0);
    else if (match.winner === 'p2') seats.add(1);
  } else {
    if (match.winner === 't1') { seats.add(0); seats.add(1); }
    else if (match.winner === 't2') { seats.add(2); seats.add(3); }
  }
  return seats;
}
```

**Синергия 2 vs 2.** Пара героев (или игроков) — это те, кто сидел в одной
команде. Пара получает победу, если её команда выиграла:

```ts
for (const team of teams) {
  // Игрок не может быть партнёром самому себе — вырожденные строки пропускаем.
  if (
    team.players.length === 2 &&
    team.players.every(Boolean) &&
    identityKey(team.players[0]) !== identityKey(team.players[1])
  ) {
    const { key, members } = pairKey(team.players[0], team.players[1]);
    const agg = playerPairAgg.get(key) ?? { members, games: 0, wins: 0 };
    agg.games += 1;
    if (team.won) agg.wins += 1;
    playerPairAgg.set(key, agg);
  }
}
```

Порог отсечения для синергий — **минимум 3 матча** (`MIN_GAMES_FOR_SYNERGY`),
иначе лидерборд выигрывают пары с одним матчем и 100 % винрейтом.

### Сценарий «1 игрок против 2 игроков» (2 vs 2)

В игре возможна ситуация, когда один игрок ведёт **сразу двух героев** против
двух соперников. В таблице это выглядит так: один и тот же игрок указан в обоих
местах одной команды.

Такие строки **не считаются ошибкой** — это полноценные матчи. При разборе
строки они помечаются:

```ts
function detectDualControl(
  players: [string, string],
  heroes: [string, string],
  team: 1 | 2,
): DualControl | null {
  if (!players[0] || !players[1]) return null;
  if (identityKey(players[0]) !== identityKey(players[1])) return null;
  return { player: players[0], team, heroes: [heroes[0] ?? '', heroes[1] ?? ''] };
}
```

Правила подсчёта:

| Что | Как считается |
|---|---|
| Матч игрока | **один раз**, а не два (иначе винрейт и число игр завышены) |
| Победа/поражение | результат команды, в которой он играл |
| Герои | **оба** героя засчитываются за этого игрока (в т.ч. в связках «игрок + герой») |
| Пара игроков | не считается синергией — игрок не является партнёром самому себе |
| Пара героев | считается синергией — эти два героя действительно играли вместе |
| Очные противостояния | игрок получает по одному матчу против каждого из соперников |

В интерфейсе такие матчи помечены бейджем **«1 игрок · 2 героя»** — в истории,
в списке игроков и в открытой карточке игрока.

### Пустое поле боя

Матч без выбранного поля **не попадает ни в один рейтинг полей** — ни отдельной
строкой, ни в график популярности. Он учитывается в общей статистике, у
игроков, у героев и на графике активности, но количество таких матчей
считается отдельно (`stats.totals.unmappedMatches`) и показывается
информационной панелью «Без поля боя».

```ts
/**
 * Поле боя для матча.
 *
 * `null`, если поле не записано или записано заглушкой («Неизвестно»).
 * Такие матчи считаются, но никогда не попадают в рейтинг полей —
 * иначе пустая категория опережала бы каждое реальное поле.
 */
export function mapBucket(match: Match): string | null {
  const map = match.map?.trim();
  if (!map) return null;
  if (isUnknownMap(map)) return null;
  return map;
}
```

Сейчас это **518 матчей из 894** — их по-прежнему видно в общей статистике,
но рейтинг полей отражает только 376 матчей с реальным полем боя.

### Нормализация названий полей

Одно и то же поле в таблице записано по-разному. Ключ группировки
(`mapKey` в `src/lib/normalize.ts`) игнорирует регистр, пробелы, дефисы,
апострофы и притяжательную форму:

```ts
export function mapKey(value: string): string {
  return canonicalName(value)
    .toLowerCase()
    .replace(/ё/g, 'е')
    .replace(/\b['‘’]s\b/g, '')   // "Santa's Workshop" -> "Santa Workshop"
    .replace(/[-–—_/]/g, '')
    .replace(/['‘’"`«»]/g, '')
    .replace(/\s+/g, '');
}
```

Так `Marmoreal(Том 1)` и `Marmoreal(Том1)`, а также `Santa's Workshop(Том 3)`
и `Santa workshop(Том 3)` — это **одно** поле (38 полей вместо 40 без
нормализации).

Отображаемое название берётся из от руки собранной вкладки `PlayerList`
(колонки I и J), если поле там есть, иначе — самое частое написание из
истории матчей.

### Скрытие фан-персонажей

Движок статистики — чистая функция, поэтому переключатель в шапке
пересчитывает всё прямо в браузере, без обращения к серверу:

```ts
const stats = useMemo(() => {
  if (!hideFan) return data.stats;
  return computeStats(data.matches, data.reference, {
    excludeHeroes: (hero) => isHomebrew(hero),
    rejectedRows: data.stats.rejectedRows,
  });
}, [hideFan, data]);
```

Скрываются только **герои** с пометкой «(фан)»: они исчезают из таблицы
героев, из топа по винрейту, из карточки «Самый частый герой» и из пар
синергий. Сами матчи при этом никуда не деваются — они по-прежнему считаются
для игроков, полей и графика по месяцам.

### Пороги лидербордов

| Порог | Значение | Зачем |
|---|---|---|
| `MIN_GAMES_FOR_PLAYER_RATE` | **20** матчей | Чтобы запись 3–0 не занимала первое место с искусственными 100 % |
| `MIN_GAMES_FOR_HERO_RATE` | **10** матчей | То же для героев |
| `MIN_GAMES_FOR_SYNERGY` | 3 матча | Для пар героев/игроков |

Порог для игроков и для героев разный: по игрокам матчей набирается больше,
поэтому 20 отсекает случайные всплески, а по героям 10 — достаточная выборка,
чтобы винрейт вообще что-то значил.

### Что показывает дашборд

| Метрика | Где считается |
|---|---|
| Всего матчей + разбивка 1 vs 1 / 2 vs 2 | `stats.totals` |
| Победы / поражения / винрейт — по игрокам | `stats.players` |
| Победы / поражения / винрейт — по героям | `stats.heroes` |
| Матчи с двойным контролем | `stats.totals.dualControlMatches` |
| Самый активный игрок | `stats.players[0]` |
| Лучший игрок по винрейту (мин. 10) | `stats.playerLeaders[0]` |
| Самый частый герой | `stats.mostPlayedHero` |
| Самое популярное поле | `stats.mostPopularMap`, `stats.maps` |
| Разбивка героев: всего / официальные / фан | `stats.heroBreakdown` |
| Лучшая синергия героев (2 vs 2) | `stats.bestHeroSynergy` |
| Лучшая синергия игроков (2 vs 2) | `stats.bestPlayerSynergy` |
| Связки игрок + герой | `stats.favouriteCombos` |
| Очные противостояния | `stats.headToHead` |
| Активность по месяцам | `stats.timeline` |

## 6. Форма матча и правила валидации

`src/components/MatchForm.tsx` (клиентский компонент) +
`src/app/api/matches/route.ts` (серверная проверка).

**Правило «герой не может повторяться»** проверяется в трёх местах:

1. **В UI** — уже выбранный герой помечается в списке как недоступный:

```tsx
{heroes.slice(0, seatCount).some((h, i) => i !== index && h === hero.name) && (
  <option disabled>{hero.name} — уже выбран</option>
)}
```

2. **В браузере перед отправкой** — список ошибок справа от формы.
3. **На сервере** — `zod` не пропустит такой матч даже если отправить
   запрос вручную:

```ts
.superRefine((value, ctx) => {
  const seen = new Set<string>();
  value.heroes.forEach((hero, index) => {
    const key = hero.toLowerCase();
    if (seen.has(key)) {
      ctx.addIssue({
        code: z.ZodIssueCode.custom,
        path: ['heroes', index],
        message: `Герой «${hero}» уже выбран в этом матче`,
      });
    }
    seen.add(key);
  });
});
```

## 7. Изображения: как хранить

Рекомендуемый вариант — **URL в отдельной вкладке `Images`**
(`Имя | Тип | URL`). Он уже реализован:

```ts
// src/lib/sheets.ts
async upsertImage(name, type, url) {
  const rows = await readRange(`'${imagesTab()}'!A1:C`);
  const targetIndex = rows.findIndex(
    (r) => (r[0] ?? '').trim() === name && (r[1] ?? '').trim() === type,
  );
  if (targetIndex >= 0) {
    await client.spreadsheets.values.update({
      spreadsheetId: spreadsheetId(),
      range: `'${imagesTab()}'!C${targetIndex + 1}`,
      valueInputOption: 'RAW',
      requestBody: { values: [[url]] },
    });
    return;
  }
  await client.spreadsheets.values.append({ /* ... [[name, type, url]] ... */ });
}
```

**Где взять сами картинки:**

| Способ | Как | Нюанс |
|---|---|---|
| **Google Drive** | загрузить файл → «Поделиться» → «Вставить ссылку» → ID вида `1AbC…` | Нужен **прямой** URL: `https://drive.google.com/uc?export=view&id=<ID>`. Обычная ссылка на просмотр не подойдёт — браузер отдаст HTML, а не картинку. |
| **GitHub / imgur** | загрузить файл, скопировать raw-ссылку | Самый простой вариант, домен не заблокирован. |
| **Яндекс.Диск** | публичная ссылка вида `https://disk.yandex.ru/i/<ID>/` | Работает как прямой URL. |

**Альтернативы и почему они хуже:**

- **Base64 в ячейке** — не делайте. Ячейка в Google Sheets ограничена
  50 000 символами, а картинка в base64 — это десятки килобайт. Таблица
  раздуется, а каждая загрузка страницы будет тянуть мегабайты.
- **Загрузка файлов через форму** — возможно, но требует отдельного
  хранилища (S3, Cloud Storage, Cloudinary) и отдельного API ключа.
  Прямой URL из Drive решает задачу без лишней инфраструктуры.
- **Внешний CDN для аватаров** (DiceBear, Gravatar) — бесплатно и без
  ручной загрузки, но это абстрактные аватары, а не портреты героев.

**Как это выглядит в интерфейсе.** Если URL не задан, приложение рисует
цветные монограммы, детерминированно вычисленные из имени — дашборд
никогда не выглядит «битым»:

```tsx
function hashName(name: string): number {
  let hash = 0;
  for (let i = 0; i < name.length; i += 1) {
    hash = (hash << 5) - hash + name.charCodeAt(i);
    hash |= 0;
  }
  return Math.abs(hash);
}
```

### Почему модальное окно съезжало

`position: fixed` позиционируется относительно вьюпорта **только если у
предка нет трансформации**. Панели приложения анимируются классом
`.animate-fade-up`, и анимация с `animation-fill-mode: both` оставляет
`transform: translateY(0)` — такой transform делает панель containing block
для `position: fixed`, и модалка центрировалась по панели (то есть по середине
всей страницы, а не экрана).

Исправлено двумя способами сразу:

1. Модалка выносится в `document.body` через `createPortal` — предок с
   трансформацией больше не участвует в позиционировании.
2. `animation-fill-mode` заменён на `backwards`, чтобы трансформация не
   задерживалась после окончания анимации.

Позиционирование задано явно:

```css
.modal-overlay {
  position: fixed;
  inset: 0;
  z-index: 60;
}

.modal-panel {
  position: fixed;
  top: 50%;
  left: 50%;
  transform: translate(-50%, -50%);
  z-index: 61;
}
```

## 13. Обновление: поля боя, игроки, таблицы, графики

Ниже — семь доработок, сделанных поверх предыдущей версии. Для каждой —
что именно поменялось в коде и почему.

### 13.1 Поле боя в 1 vs 1 (колонка G)

**Что было не так.** Колонка `G` («Поле 1 vs 1») читалась всегда — это видно
в `src/lib/parse.ts`:

```ts
export const MATCH_COLUMNS = {
  // ...
  map1v1: 6,   // G — «Поле 1 vs 1»
  map2v2: 10,  // K — «Поле 2 vs 2»
};
```

Настоящая причина жалоб была в другом: **выпадающий список полей для 1 vs 1
был неполным**. Вкладка `PlayerList` ведётся вручную, и 8 полей, которые
реально играли в 1 vs 1, в колонке `J` отсутствовали — включая самое
популярное поле таблицы, `Globe Theatre(Удары судьбы)`. Выбрать его было
невозможно.

**Что сделано.** Справочник полей теперь — объединение колонок `I`/`J` и всех
полей, встречающихся в истории матчей:

```ts
column(8).forEach((name) => addMap(name, '2v2', true));  // I — Поля 2 на 2
column(9).forEach((name) => addMap(name, '1v1', true));  // J — Поля 1 vs 1
for (const match of matches) {
  const name = mapBucket(match);
  if (name) addMap(name, match.mode, false);
}
```

Поле попадает в список того режима, в котором оно **реально игралось**, даже
если в справочнике оно указано только для другого. Сейчас в списке 1 vs 1 —
39 полей, из них 12 встречаются только в 1 vs 1 (`Raptor Paddock`,
`T. Rex Paddock`, `Azuchi Castle(Томоэ vs Ода)` и другие).

### 13.2 «Титан-Гриша» — это игрок, а не герой

В строке 793 в колонку героя попал игрок `Титан-Гриша`. Он же стоит в
колонке `C` вкладки `PlayerList` — то есть это реальный участник, который
просто забыл поменять героя.

Список героев теперь фильтруется по чёрному списку, а список игроков — нет:

```ts
/** Герои, которые по ошибке оказались в колонке героя. */
const HERO_DENYLIST = new Set(['титан-гриша']);

export function isExcludedHero(value: string): boolean {
  return HERO_DENYLIST.has(identityKey(value));
}
```

| Список | «Титан-Гриша» |
|---|---|
| Справочник героев | исключён |
| Таблица героев, топ по винрейту, пары синергий | исключён |
| Справочник игроков | остался (он и правда играл — 4 матча) |

**Отдельно про «Неизвестно».** В строках 410, 411, 413, 414 в колонке
«Игрок 2» стоит «Неизвестно» — это заглушка, а не человек. Такие имена
исключаются из списка игроков и из статистики игроков, но **сами матчи
засчитываются полностью** — победа реального соперника никуда не девается.

```ts
const PLACEHOLDER_VALUES = new Set([
  'неизвестно', 'не известно', 'неизвестный', 'не указан', 'без имени',
]);
```

### 13.3 Таблица героев: две колонки режимов

В таблице героев теперь две группы колонок — «1 vs 1» и «2 vs 2» — у каждой
свои игры, победы, поражения и винрейт, разделённые вертикальной линией.
Таблица игроков осталась прежней (одна общая группа).

```tsx
<th className="stat-label border-y border-ink-700 bg-ink-850/60 py-1.5 text-center text-azure-300"
    colSpan={4}>1 vs 1</th>
<th className="stat-label border-y border-l border-ink-700 bg-ink-850/60 py-1.5 text-center text-gold-300"
    colSpan={4}>2 vs 2</th>
```

Реализовано как один компонент с пропом `layout: 'combined' | 'split'`
(`src/components/EntityTable.tsx`), а не двумя разными таблицами.

### 13.4 Рейтинг полей: без пустой категории, с топ-героем и топ-победителем

Матчи без поля боя (518 из 894) **исключены** из рейтинга полей, из графика
популярности и из карточки «Самое популярное поле» — там всегда реальное
поле. Их количество вынесено в отдельную информационную панель «Без поля
боя».

У каждого поля появились два новых показателя:

| Столбец | Что считает |
|---|---|
| **Топ-герой** | герой, сыгранный на этом поле чаще всего |
| **Топ-победитель** | игрок, выигравший на этом поле больше всех (плюс его счёт `победы/игры`) |

```ts
export interface MapStats {
  name: string;
  matches: number;
  games: number;
  wins: number;
  winRate: number;
  topHero: { name: string; games: number } | null;
  topPlayer: { name: string; wins: number; games: number } | null;
}
```
